# TUR-002: Where no apostrophe is written (exceptions and noisy text) the name/suffix boundary has no orthographic cue

## Question and scope

When a suffix follows a proper name without an apostrophe, because the standard allows it or because the writer omitted it, what boundary information remains? Scope: standard written Turkish plus constructed noisy text, Latin script, PERSON with institution and common-noun contrasts. Excludes measured prevalence of omission and any claim about particular communities. Complements [TUR-001](TUR-001.md).

## Observation

The TDK apostrophe page, as summarized, lists exceptions where the apostrophe is not used: suffixes after institution and organization names (`Türkiye Büyük Millet Meclisine`, `Türk Dil Kurumundan`), derivational and plural suffixes on proper names (`Türklük`, `Türkçe`, `Ahmetler`), and names that already end in a possessive suffix [TUR-S001](../sources.md#tur-s001). So for a personal name, plural `-ler` such as `Ahmetler` is written without an apostrophe, and the plain token is the name plus a morpheme that can mean a family or group rather than one person. A search-result gloss attributes the institution-name rule to earlier TDK guides, which was not verified.

Noisy text is a separate matter. Küçük and Steinberger report relaxed capitalization, diacritics-based lexical expansion and tweet normalization as modifications to improve Turkish tweet NER [TUR-S010](../sources.md#tur-s010); Küçük reports informal name variants, including capitalization inconsistencies and spelling mistakes, in a tweet dataset [TUR-S011](../sources.md#tur-s011). Both are abstract-level evidence: neither abstract names apostrophe omission, so that omission as a pattern is an **author hypothesis**, not a sourced observation. A news explainer asserts consonant softening does not apply to proper names (`Mehmet'im`, not `Mehmedim`) [TUR-S015](../sources.md#tur-s015); this is a secondary lead, not grammar evidence, and the common-noun contrast (`kitap` to `kitabı`) is background knowledge not sourced here.

Confidence **medium** for the exception list, **low** for anything about noisy usage.

## NER hypothesis

For tokens with no apostrophe, a character-level or context-sensitive boundary model will beat both whitespace-only and apostrophe-cut candidates on exact spans, whereas apostrophe-cut candidates will under-segment noisy variants. The hypothesis is challenged if a simple apostrophe rule performs as well on matched apostrophe-omitted tokens, or if omission is too rare in the target domain to affect results. Classification of `Ahmetler`-type plurals is a separate policy question and is not predicted.

## Evidence handoff

Positive cases: personal names plus suffix with apostrophe omitted, built as matched pairs against ex-01 of TUR-001 with an explicit perturbation label. Hard negatives: institution names with unapostrophized suffixes, plural and derivational forms, common nouns that coincide with names. Variation axes: apostrophe present, absent, or replaced by another character; capitalization retained or lost.

Destination: `ner-evidence`; no issue exists. Disposition: **ready for owner review as a proposal**, subject to qualified Turkish review of every example and to the owner's annotation policy.

## Evaluation handoff

Proposed slice `tr-no-apostrophe`: matched apostrophe-present versus apostrophe-absent inputs, same names and suffixes, same model. Question: how much exact-span recall is lost when the cue is deleted, and by which suffix classes? Failure condition: no measurable drop, in which case apostrophe handling is not a priority for the tested domain.

Destination: `ner-eval`; no issue exists. Disposition: **deferred** until reviewed evidence exists. Hold fixed the evidence snapshot, model, decoding and scoring contract; report slice denominators, exact-span precision/recall and boundary-error types. No threshold is proposed.

## Implementation options

Options: no change; apostrophe-cut baseline; suffix-list stripping (risk: truncating names that end like suffixes); a trained boundary model on augmented data. Tradeoff: suffix-list stripping is cheap but known to over-cut names.

Destination: `fastner`; proposed experiments only, **deferred**; no downstream code was inspected for this finding.

## Limitations and review

Exception wording comes from a summary of the TDK page. The informal-usage claims rest on abstracts that do not name apostrophe omission. Consonant softening on names is documented only by a newspaper explainer. No attested noisy examples were collected, so all noisy rows are constructed.
